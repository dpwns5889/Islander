# BiomeDefender (가칭)

지형 조각을 맞춰 섬을 만들고, 마을을 세워 해적을 막는 **퍼즐 + 디펜스** 게임입니다.
3D 로우폴리 장면을 도트 그래픽처럼 렌더링합니다.

![전투 화면](docs/images/battle.png)

| 항목 | 내용 |
|---|---|
| 장르 | 지형 조각 퍼즐 + 타워 디펜스 |
| 엔진 / 언어 | Godot 4.7.2 (Forward+), GDScript, GLSL 계열 셰이더 |
| 플랫폼 | PC (마우스 조작), Windows에서 개발 |
| 개발 | 1인 개발, 진행 중 (v0.61) |
| 규모 | GDScript 약 4,200줄, 셰이더 3개, 점검 스크립트 41개 |

## 게임 흐름

한 판은 **준비 단계 → 전투 단계**를 반복하며, 30웨이브를 버티면 승리하고 이후 무한 모드로 이어집니다.

- **섬 만들기:** 4~7칸 폴리오미노 18종을 회전해 놓습니다. 평원·모래·숲·산·바다가 각각 건설 가능 여부와 이동에 영향을 줍니다.
- **위험과 보상:** 땅을 넓힐수록 마을은 커지지만 적도 강해집니다. 섬을 나누면 방어에 유리한 대신 병사가 항구와 보트로 이동해야 합니다.
- **마을 성장:** 건물 18종을 짓고 강화·진화시키며, 14개 연구로 이루어진 테크트리를 올립니다. 본부 레벨에 따라 생산 가능한 영역이 넓어집니다.
- **전투:** 병사 6종과 적 5종이 자동으로 싸우고, 플레이어는 집결 지점을 지정하며 배속과 카메라를 조절합니다.
- **피해 관리:** 건물 피해는 다음 웨이브까지 남습니다. 파손 단계에 따라 모델이 바뀌고 성능이 떨어지며, 골드를 써서 수리합니다.

## 기술적 특징

### 1. 3D를 도트 그래픽으로 렌더링

![도트 화면 비교](docs/images/pixel_compare.png)

단순히 해상도를 낮추면 카메라가 움직일 때 픽셀이 떨리고 글자가 뭉개집니다. [`pixel_view.gd`](assets/scripts/pixel_view.gd)에서 이렇게 해결했습니다.

- 3D를 세로 360픽셀 `SubViewport`에 그린 뒤 최근접 필터로 확대합니다.
- 카메라를 **도트 격자 단위로만** 옮기고, 남은 소수점 이동은 화면을 밀어 보정합니다.
- 글자는 원래 해상도의 별도 뷰포트에 그려 겹치고, 마우스 광선은 도트 화면 좌표로 변환합니다.
- 외곽선은 [깊이 버퍼 후처리](assets/shaders/pixel_post.gdshader)로 그립니다. 화면을 복사하면 반투명 격자와 미리보기가 사라져서 **덮어 그리는 방식**으로 바꿨습니다.
- 카메라를 낮게 기울이면 땅 전체가 외곽선으로 칠해지는 문제는, 기울기와 도트 크기에 맞춰 판정 기준을 조절해 막았습니다.

### 2. 어느 배율에서든 1도트인 격자

선 메시로 그린 격자는 배율에 따라 굵기가 1~2도트로 섞였습니다. 화면 공간 미분(`dFdx`, `dFdy`)을 쓰는 [셰이더](assets/shaders/grid.gdshader)로 바꿨습니다.
판정 구간이 픽셀 간격보다 0.1%만 좁아도 일부 배율에서 줄이 사라지는 것을 발견했고, 배율을 훑는 [렌더 점검](tests/grid_render.gd)으로 264개 조건을 확인합니다.

### 3. 격자 기반 길찾기와 섬

물리 엔진 대신 `AStarGrid2D`를 씁니다. 병사와 적은 땅, 해적선과 보트는 바다 격자로 다닙니다.
섬이 나뉘면 병사는 항구의 보트로 건너고, 바닷길이 막히면 해적은 느린 속도로 바다를 걸어 건너는 별도 격자를 사용합니다.
([`battle.gd`](assets/scripts/battle.gd), [`field.gd`](assets/scripts/field.gd))

### 4. 예고와 일치하는 무작위 웨이브

웨이브마다 정해진 전투력 예산 안에서 적 종류를 무작위로 뽑습니다.
난수 시드를 `(판 시드, 웨이브 번호)`로 만들어, 준비 단계의 **적 예고와 실제 전투가 항상 같습니다.**

### 5. 데이터 중심 설계

- 비용·체력·공격·웨이브 같은 밸런스 수치는 [`balance.gd`](assets/scripts/balance.gd)에 모았습니다.
- 건물 모델은 데이터에 종류 이름만 적으면 `종류_레벨_번호(_dmg1|_dmg2)` 파일 규칙에 따라 연결됩니다. Blender 모델 11종류(파손 단계 포함 `.glb` 288개)를 적용했습니다.
- 전투는 `tick(dt)`로 계산을 나눠, 배속을 올려도 움직임이 튀지 않고 화면 없이도 전투를 점검할 수 있습니다.

## 개발 방식

- **기획 문서 우선:** 규칙과 수치를 [기획서](docs/GameDesign.md)에 먼저 적고 구현합니다. 버전별 변경 이력을 함께 관리합니다.
- **자동 점검:** 로직 점검(`*_check.gd`)과 실제 씬을 띄우는 흐름 점검(`*_flow.gd`) 41개를 자체 작성한 스크립트로 실행합니다.
- **Git 작업 흐름:** 작업별 브랜치와 Pull Request를 사용하고, 바이너리 파일은 Git LFS로 관리합니다.
- **AI 협업:** AI 코딩 도구(Claude Code)와 함께 설계 검토, 구현, 검증을 진행했습니다.

## 실행 방법

[Godot 4.7.2](https://godotengine.org/)와 [Git LFS](https://git-lfs.com/)가 필요합니다.

```bash
git lfs install          # 먼저 하지 않으면 모델 대신 안내 파일만 받아집니다
git clone <저장소 주소>
```

Godot에서 `project.godot`을 열고 실행(F5)합니다. 전체화면으로 시작하며 `Alt+F4`로 종료합니다.

### 조작

| 단계 | 입력 | 동작 |
|---|---|---|
| 준비 | 좌클릭 | 조각 배치, 건설, 건물 선택 |
| 준비 | 우클릭 / `R` | 조각 회전 |
| 준비·전투 | 마우스 휠 | 확대/축소 |
| 전투 | 좌클릭 드래그 | 카메라 이동 |
| 전투 | 우클릭 드래그 | 카메라 회전, 기울기 |
| 전투 | 휠 버튼 클릭 | 병사 이동 |
| 언제나 | `P` | 도트 화면 켜고 끄기 |

### 점검 실행

```bash
godot --headless --path . --import
for f in tests/*_check.gd tests/*_flow.gd; do
  godot --headless --path . --script "$f"
done
godot --path . --script tests/grid_render.gd   # 렌더 점검은 창이 필요합니다
```
